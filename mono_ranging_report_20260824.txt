実施日: 2026-08-24 / ブランチ: feature/mono-ranging(main未変更)
判定: **タスク1〜4すべて完了**。終了条件A。

【背景】
実機カメラがRaspberry Pi 5 + Piカメラ(単眼、深度なし)に決定したため、
yolo_trash_detector.pyの「BBox内の深度中央値で測距」が使えなくなった。
代わりに「対象は床(z≈0)に接している」という仮定と、カメラ高さh・
下向き角θが既知であれば画像座標から床上の3D位置を一意に求められる
という原理(depth_trash_detector.pyの床面自己較正と同じ数式)を使い、
深度不要の測距方式を実装した。

================================================================================
タスク1: 測距モジュールの実装
================================================================================
src/amr_bringup/scripts/mono_ranging.py を新規作成。
  - bbox_ground_contact_point(): BBoxの【下辺の中心】を接地点として使用
    (BBox中心を使うと対象の高さ分だけ実際より遠くと誤って推定するため)
  - ground_plane_range(): y'=(v-cy)/fy, x'=(u-cx)/fx から
    depth=h/(sinθ+y'cosθ) で光線距離を求め、カメラ光学フレーム
    (x=right,y=down,z=forward)での3D点(x_opt,y_opt,z_opt)=
    (x'・depth, y'・depth, depth) を返す
  - 妥当性チェック: 分母(sinθ+y'cosθ)がmin_denom(既定1e-3)以下なら
    「地平線より上を向いている(床と交差しない)」としてNoneを返す
  - project_ground_point_to_pixel(): 逆演算(順算)。往復検証・校正
    ツールの両方で使う共通関数

出力を光学フレームでの3D点にしたことで、depth方式と全く同じ経路
(PointStamped→TF変換→trash_map_publish.py)にそのまま流せる設計に
なっている(URDFのカメラ取り付け位置がh・θの回転・並進を担うため、
mono_ranging.py側では床面仮定の幾何のみを計算すればよい)。

【単体テスト: tools/test_mono_ranging.py】
h=0.20m, θ=15°、既知距離0.3/0.5/1.0/2.0m(各横方向0/±0.15mも含め計12点)
で順算→逆算の往復誤差を検証:
  **最大誤差 = 2.22e-16 m(機械精度レベル、<1mmを大幅にクリア)**
  → 全12点でPASSED

タスク2: yolo_trash_detector.pyへの統合
================================================================================
- パラメータ ranging_mode('depth'既定 | 'mono')、camera_height(既定0.20)、
  camera_pitch_deg(既定15.0)を追加
- ranging_mode='mono'選択時は depth_topic を購読しない
  (create_subscriptionをranging_modeで条件分岐)
- image_cb()を_range_box_depth()/_range_box_mono()の2メソッドに分離し、
  ranging_modeで呼び分ける形にリファクタリング(depth方式のロジックは
  完全に維持、動作を変えていない)
- map座標変換・重複抑制・境界棄却は既存のtrash_map_publish.py
  (TrashMapPublisher)をそのまま使用、変更なし
- モジュールdocstring・パラメータ宣言部に精度特性をコメントで明記:
  「θ誤差1°で2m先が約30cmずれる。近距離ほど正確。遠距離の検出は
  方向の当たりとして使い、接近しながら再検出で精度を上げる前提」

【起動確認】
ノード単体を ranging_mode:=mono, camera_height:=0.22,
camera_pitch_deg:=17.0 で起動し、ログで
"YoloTrashDetector started (... ranging_mode=mono,
camera_height=0.22m, camera_pitch=17.0deg ...)" を確認、depth_topic
未購読・エラーなしで正常起動することを確認済み。

================================================================================
タスク3: 校正ツール
================================================================================
tools/calibrate_camera_pose.py を新規作成。
- 入力: 床の既知距離にマーカーを置いた画像上の接地点画素座標(u,v)と
  真の床面座標(x,y)の観測点リスト(JSON)
- 最小二乗フィットでh・θを推定
- 【重要】scipy.optimize が本環境ではnumpy2との非互換で壊れていた
  (`ImportError: cannot import name 'Inf' from 'numpy'`)ため、依存を
  増やさず自前の段階的格子探索(粗い格子→周辺を絞って再探索を
  4ラウンド)で最小二乗フィットを実装。scipyへの依存を避けたことで、
  実機環境でも同じ問題に遭遇するリスクを回避している
- docstring冒頭に「URDFの公称値を信じず、実機で必ず校正すること」を明記
- 自己テスト(--self-test): 合成データ(h=0.22m, θ=17.3°から順算した
  5観測点)でフィットが正しく復元できるかを検証
  **結果: h誤差=0.00004m(0.04mm)、θ誤差=0.0016° → PASSED**

タスク4: 検証
================================================================================
【1. 単体テストの往復誤差】(再掲)
  最大誤差 2.22e-16 m(機械精度、<1mm合格)

【2. 感度解析】(tools/test_mono_ranging.py sensitivity_table())
h(±1cm)・θ(±1°)の誤差が距離推定に与える影響:

| X_true[m] | h+1cm誤差[m] | h-1cm誤差[m] | θ+1°誤差[m] | θ-1°誤差[m] |
|-----------|--------------|--------------|-------------|-------------|
| 0.30      | +0.0150      | -0.0150      | -0.0111     | +0.0117     |
| 0.50      | +0.0250      | -0.0250      | -0.0243     | +0.0265     |
| 1.00      | +0.0500      | -0.0500      | -0.0835     | +0.0994     |
| 1.50      | +0.0750      | -0.0750      | -0.1767     | +0.2300     |
| 2.00      | +0.1000      | -0.1000      | -0.3002     | +0.4272     |
| 2.50      | +0.1250      | -0.1250      | -0.4506     | +0.7022     |

**2.0m地点でθ+1°誤差 = -0.30m** — 指示で示されていた「θ誤差1°で
2m先が30cmずれる」と数値が完全に一致し、実装が理論通りであることを
確認した。h誤差は距離にほぼ線形(1cm誤差→距離に比例した誤差)、
θ誤差は遠方ほど非線形に急拡大する。

【3. YOLOのval画像でのmono測距の統計】
val画像(51枚)にYOLO(conf=0.35)を適用し、検出された全BBoxに対し
ranging_mode='mono'相当の計算(h=0.20, θ=15°, fx=fy=500,cx=320,cy=240
の仮定値、実写画像の実際のカメラ内部パラメータは不明なため典型値で近似)
を実施:
  検出BBox総数: 101
  地平線より上と判定され測距不能(妥当な棄却): 20
  測距成功: 81
  前方距離X: min=0.233m, max=10.587m, mean=1.395m
  横方向Y: min=-3.468m, max=5.574m, mean=-0.075m
  **期待範囲(0.2≤X≤3.0m, |Y|<1.5m)内: 70/81 (86.4%)**

【所見】残り13.6%が範囲外になった主因は、これらの実写画像が
実際には h=0.20m/θ=15° という想定条件で撮影されたものではない
(人がスマートフォンを様々な高さ・角度で持って撮影した写真)ため、
mono_ranging.pyが前提とする幾何条件と実際の撮影条件が一致していない
ことによる。これはモジュール自体の不具合ではなく、「実機で校正
(タスク3のツール)しないと精度が出ない」という設計上の性質を
そのまま反映した結果であり、想定通りの挙動と言える。

================================================================================
実機で校正する際の手順(タスク3ツールの使い方)
================================================================================
1. ロボットにカメラを取り付けた実機状態で、床に既知の距離
   (例: 0.5m, 1.0m, 1.5m、できれば横方向にもずらして3〜5点以上)に
   マーカー(紙くずでも可)を置き、カメラで撮影する
2. 撮影した画像を開き、各マーカーの「接地点」(マーカーが床に触れて
   いる位置)の画素座標(u,v)を読み取る(画像ビューアのピクセル座標
   表示機能や、yolo_trash_detector.pyのBBox下辺中心と同じ考え方で
   目視特定する)
3. 観測点をJSON形式でファイルに保存する:
   [
     {"u": 320, "v": 300, "x": 0.5, "y": 0.0},
     {"u": 320, "v": 210, "x": 1.0, "y": 0.0},
     {"u": 320, "v": 160, "x": 2.0, "y": 0.0}
   ]
   (u,v=画素座標、x=カメラからの真の前方距離[m]、y=真の横方向[m]、
   正面に置いたならy=0でよい)
4. 以下を実行:
   python3 tools/calibrate_camera_pose.py --observations obs.json \
       --fx <camera_infoのfx> --fy <fy> --cx <cx> --cy <cy>
5. 出力される camera_height / camera_pitch_deg の推定値を、
   full_autonomy.launch.py または起動時のパラメータ指定で
   yolo_trash_detector.py に渡す(ranging_mode:=mono と併用)
6. 事前に --self-test で校正ツール自体が正しく動くこと(合成データでの
   フィット復元)を確認しておくと安心

================================================================================
残った問題と次の一手
================================================================================
1. 本タスクの検証はYOLOのval画像(実際のh/θとは異なる条件で撮影)を
   使った「範囲の妥当性」チェックにとどまり、絶対精度の検証はできて
   いない(指示通り、真値がないため範囲チェックのみを実施)。実機組立後、
   タスク3のツールで校正し、既知距離での実測誤差を確認することが
   次の必須ステップ。
2. full_autonomy.launch.pyにはranging_modeを選択するlaunch引数を
   追加していない(タスクの指示範囲がyolo_trash_detector.py本体への
   パラメータ追加までだったため)。実機投入時にlaunchファイル側からも
   切り替えられるようにするかは、実機統合時に別途検討が必要。
3. mono測距は遠距離ほど不正確という性質上、遠方での検出結果を
   そのままpick位置として使うのは危険。patrol_and_collect.py側で
   「一定距離まで接近してから再検出する」制御を入れる設計が
   将来的に必要になる(本タスクのdocstringに明記済みだが、
   制御ロジック自体は未実装)。
