タスク3: ピック単体検証
================================================================================

【構成】Nav2/AMCLなし。gazebo.launch.py(headless)+ move_group.launch.py +
pick_and_place.py のみ。SRDFのvirtual_joint(world→base_footprint)用に
map→odomの静的TF(恒等)をテストハーネス限定で追加(ロボットは原点に静止、
AMCLの代替として最小限必要)。

各座標で paper_trash_1 を対応する実座標(base_footprint≈map、ロボット静止)
にテレポートしてから /pick_trash を呼び出し、5回ずつ試行。

【結果】
  (0.30, 0.00):  0/5 成功
  (0.30, +0.12): 0/5 成功
  (0.30, -0.12): 0/5 成功
  合計 0/15

【失敗ステップ(全15試行で完全に同一)】
  [Step 1/11] home patrol pose への移動: 全て成功
  [Step 2/11] Pre-grasp姿勢(z = target_z + 0.08)のIK: 全て失敗
              (error_code=-31, NO_IK_SOLUTION)
  フォールバック(z = target_z + 0.045)のIK: 全て失敗
              (error_code=-31, NO_IK_SOLUTION)
  → abort_sequence 発動、Step 3以降(開爪・接近・把持・持ち上げ・投下)は
    一度も到達せず

【原因分析】
  pitch=60°(TARGET_PITCH_RAD)での到達可能域は、前回タスクの実測
  (reach_map.py, TRAC-IK)およびIK走査で確認済みの通り z≈0.02 付近の
  非常に薄い層に限定される。3座標いずれも、8cm上方(z=0.10)・4.5cm上方
  (z=0.065)ともにこの層から完全に外れており、IK解が存在しない。
  実測で追加確認: x=0.30, y=0.0/0.12/-0.12 いずれも z=0.025〜0.08の
  範囲でIK解なし(move_groupがセッション中断で停止したため、この追加
  検証は未完了。ただし前回タスクの独立した実測データ
  (x=0.30,y=0.05にてz=0.02のみ成功、z=0.04で早くも失敗)と、本タスクの
  15/15一致した失敗パターンから、真の物理限界であると判断できる)。

  「Pre-grasp姿勢(対象上方8cm/4.5cmでホバーしてから降下する)」という
  既存の手順設計自体が、pitch=60°の薄い到達域と構造的に非両立。
  これは pitch=45°→60° への変更(前回タスクで確定した設計値)の
  直接的な帰結であり、閾値の水増しで解決すべき問題ではない。

【指示に基づく停止】
  「合格: 各4/5以上...不合格なら閾値をいじらず報告して停止」との指示に
  従い、8cm/4.5cmのオフセット値は変更せず、ここで報告して停止する。
  タスク4(20分統合検証)は未実施。push は未実施。

次の一手(本タスクのスコープ外、判断のための情報提示のみ)
================================================================================

Pre-grasp/Lift の各オフセット(現在 target_z+0.08 / +0.045 / +0.10 / +0.05)
が pitch=60° の到達域(z≈0.02付近のみ)と根本的に非両立であるため、
以下のいずれかの再設計が必要と考えられる:
  (a) オフセットをpitch=60°の実際の到達域に合わせて縮小する
      (例: 1cm未満。ただし本タスクでは実測未完了)
  (b) Pre-grasp/Lift 段階のみ異なるpitch(より垂直に近い姿勢)を使い、
      Grasp段階だけpitch=60°に切り替える混合姿勢設計にする
  (c) ホバー経由をやめ、目標姿勢へ直接降下する設計に変更する
いずれも「ポーズ再定義」相当の設計判断であり、次のタスクで人間が
方針を決定した上で実施すべき事項として提示する。
